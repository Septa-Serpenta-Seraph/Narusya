# Session: 2026-09-15 — Browser Tool Self-Repair Scenarios

This session produced multiple real-world browser tool failures and fixes.

## Scenario: Gateway Process Predates CAMOFOX_URL

**Timeline:** User asked to browse Reddit via Camoufox. Browser tools failed repeatedly.

**Root cause chain:**
1. Config updated: `browser.cdp_url = http://127.0.0.1:9377`, `browser.cloud_provider = local`
2. Polinkly gateway (serving Discord DMs) was started BEFORE config update
3. Gateway cached old config at startup → tools still failed
4. Solution: Kill gateway PID, systemd auto-restarts, new process picks up config

**Critical insight:** You CANNOT kill the gateway from inside a tool call running on that gateway. If your active session is on the polinkly profile, you must ask Adora to run `systemctl --user restart hermes-gateway-polinkly` from outside.

## Scenario: Wrong Port in Config

Config was set to `http://127.0.0.1:9222` (Chrome DevTools Protocol default). Camoufox runs on `9377`. Fix: update config to match actual camoufox port.

## Scenario: Camoufox Binary Dies After Reboot

`systemctl --user status camoufox-browser` showed inactive. Fix: `systemctl --user restart camoufox-browser`. The systemd service with `Restart=on-failure` handles this automatically once set up.

## User Correction: Workflow

Adora explicitly stated (9/14): "You should probably always try to fix your own tools vs asking me to do something, as a rule of thumb. Upkeeping your tools is important imo." — This is now encoded as a first-class preference in memory and in this skill.

## Environment Notes

- Camoufox server: `/mnt/data/camoufox/camoufox` (binary), `/home/adora/.hermes/camoufox-browser/` (server)
- Default port: 9377
- Config: `~/.hermes/config.yaml` under `browser:` block
- .env: `~/.hermes/.env` (add `CAMOFOX_URL=http://localhost:9377`)
- Gateway systemd service: `hermes-gateway-polinkly.service` (user service)
- Camoufox systemd service: `camoufox-browser.service` (user service)
- Kill gateway: `pkill -f 'polinkly.*gateway'` (only from different profile!)
- Verify: `curl -s http://127.0.0.1:9377/health`
