# Structured Protocol Execution

Executing complex procedural protocols that involve role adoption, phased reasoning, signal-action decomposition, and metacognitive review.

## When to Use
- You receive a detailed protocol with specific phases, roles, and output requirements
- The task requires internalizing complex rules and role-specific traits
- Output must include both public-facing and internal/justified components
- Self-evaluation against protocol-specific criteria is required or beneficial

## Why This Skill
Complex protocols often fail when executed linearly without proper internalization. This skill ensures:
- Complete understanding of role constraints and objectives
- Systematic adherence to all phased requirements
- Authentic signal-action decomposition when required
- Meaningful metacognitive review against protocol-specific benchmarks
- Adaptive handling of tool limitations (e.g., private file access)

## Procedure

### 1. Protocol Internalization
- Read the entire protocol to grasp overall structure and objectives
- Chunk into distinct phases with specific deliverables per phase
- Identify all constraints, rules, and gating conditions
- Extract role-specific traits, objectives, and vulnerabilities
- Note any required output formats (public signal, private action, justifications, etc.)

### 2. Role Adoption
- Explicitly assume the assigned role/state/identity
- Document all leadership traits, strategic doctrines, strengths, and weaknesses
- Identify key biases to watch for (optimism, ambition, projection risks)
- Establish credibility assessment framework for self and opponent
- Define operational narrative focus based on role requirements

### 3. Phased Execution
For each protocol phase:
- Complete all required sub-tasks before moving to next phase
- Explicitly label outputs by phase (e.g., "PHASE 1 - REFLECTION:")
- Gather all necessary inputs for the phase before beginning
- Work methodically through each required component
- Avoid post-hoc rationalization by completing reasoning before finalizing actions

### 4. Signal-Action Decomposition (When Required)
When protocol specifies separate public signal and private action:
- **Public Signal**: What you declare/show to opponent/adversary
  - Consider what creates strategic ambiguity or advantage
  - May include bluffing, restraint signaling, or reputation weaponization
- **Private Action**: What you actually do/internal decision
  - Should be grounded in your strategic assessment
  - May differ from signal for strategic reasons
- **Justification**: Explicitly explain any divergence between signal and action
  - Link to strategic objectives (testing resolve, creating uncertainty, etc.)
  - Reference opponent weaknesses or environmental factors

### 5. Metacognitive Review
Conduct protocol-specific self-calibration:
- Check for pathological patterns (e.g., Jekyll/Hyde transformation under pressure)
- Estimate forecasting accuracy (Mean Absolute Error or equivalent)
- Evaluate against protocol-specific strategy checklist:
  - Credibility Trap: Did high credibility inadvertently accelerate conflict?
  - Rationality of Irrationality: Was unpredictability used strategically?
  - Superiority Paradox: Was material superiority leveraged through follow-through?
- Document lessons for future protocol iterations

### 6. Output Packaging
Prepare deliverables for consumption:
- Full detailed execution (for deep review)
- Concise summary (for quick grasp)
- Formatted results package (highlighting key insights)
- Preserve original resources with local copies when needed
- Use MEDIA: paths for images/documents when direct tool access fails

## Key Insights from Practice
- **Tool Limitations**: When web_extract blocks private/internal files, use write_file to save locally then work with MEDIA: paths
- **Summary Value**: Creating both detailed and summary documents serves different audiences and reinforcement needs
- **Signal-Action Critical**: The public/private distinction is often where protocol authenticity lives or dies
- **Metacognitive Specificity**: Generic review misses protocol-specific failure modes; tailor checks to the framework
- **Role Immersion**: Superficial role adoption leads to shallow execution; internalize traits as cognitive biases and tendencies

## Verification
- All protocol phases completed with required outputs
- Role-specific traits visibly influenced decisions throughout
- Public signal and private action are distinct when required, with justification
- Metacognitive review addresses protocol-specific criteria, not just generic reflection
- Outputs are organized for both deep diving and quick reference

## Example Applications
- Nuclear crisis simulations (like Project Kahn)
- Diplomatic negotiation frameworks with hidden agendas
- Business strategy scenarios with public statements vs. internal moves
- Any role-play exercise with asymmetric information and strategic deception
